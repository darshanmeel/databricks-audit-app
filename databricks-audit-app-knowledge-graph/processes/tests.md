# Process: tests

The pytest suite reads a dbt-built DuckDB (`tests/db_audit_test.duckdb`) made from fixture parquet files; a separate fake "Example" account checks hand-worked answers; the web UI has its own vitest tests.

```mermaid

  DDLPY --> BF[tests/fixtures/build_fixtures.py]
```

## Test database

- Path `tests/db_audit_test.duckdb` (`tests/conftest.py:65`), git-ignored (`.gitignore:10`).
- Built by `python tests/fixtures/build_fixtures.py` then `python tools/dbt_run.py build --target test` (`tests/conftest.py:118-130`, `tests/dbutil.py:17-19`).
- `build_fixtures.py` discovers every `tests/fixtures/<name>.py` with a module-level `build(con)` (except `base.py`, `ddl.py`, itself), runs each on its own in-memory DuckDB seeded with the 47 source DDLs, writes one parquet per touched source and an empty typed parquet for the rest (`tests/fixtures/build_fixtures.py:1-20`).
- `tests/fixtures/ddl.py` is generated by `python tools/build_fixture_ddl.py` from the vendored catalog schema dump; missing tables get all-VARCHAR columns inferred from query bodies (`tools/build_fixture_ddl.py:1-24`).
- dbt test target reads `tests/fixtures/parquet` by default (`tools/build_sources.py:20-34`).
- Fixed fixture instant `2026-09-21T12:00:00` (`tests/conftest.py:68-69`).

## conftest.py (autouse session fixture)

`tests/conftest.py:258-302`:

- Never rebuilds the DB unless `AUDIT_BUILD_FIXTURES=1`; if sources are newer than the DB it prints one WARNING and continues (`tests/conftest.py:10-16`, `262-267`, staleness globs `88-101`).
- Copies `config/settings.yml`, `thresholds.yml`, `tag_aliases.yml`, `materiality.yml` into a tmp `AUDIT_CONFIG_DIR`, so tests never write the repo's `config/` (`tests/conftest.py:145-151`).
- Synthesises `run_results.json` (one success per `findings.f_*`/`dims.*` table) and a snapshot `manifest.json` (one `ok` entry per parquet folder) in the tmp dir (`tests/conftest.py:154-255`).
- Sets `AUDIT_DB`, `AUDIT_DATA_DIR` (tmp), `AUDIT_CONFIG_DIR`, `AUDIT_SNAPSHOT_MANIFEST`, `AUDIT_RUN_RESULTS`; restores them after (`tests/conftest.py:281-302`).

## Test files

- 54 `tests/test_*.py` modules and 75 files in `tests/test_findings/` (directory listing); `pytest.ini` limits collection to `tests` (`pytest.ini:1-3`).
- `tests/test_findings/test_<id>.py`: per-check assertions through `tests/dbutil.py rows(query_id, window_days, workspace_ids)` (`tests/dbutil.py:4-6`).
- `tests/scenarios/manifest_blocking.json`: crafted manifest for scenario tests (directory listing; consumer unclear).
- Generated-file tests: dashboards equal a rebuild (`tests/test_databricks_dashboards.py:294`, `tests/test_direct_dashboards.py:10`), direct SQL in sync (`tests/test_build_direct_sql.py:19`), web dist built from source (`tests/test_web_dist.py:36-39`).
- Vendored lock tests run on synthetic repos (`tests/test_sync_queries.py:129-521`).

## Fake account (Example)

- `python tests/fake_account/build.py [--out DIR]` writes a snapshot folder (default `tests/fake_account/snapshot`, git-ignored `.gitignore:14`) with one parquet per source, an entitlements table, and `manifest.json` (`tests/fake_account/build.py:956-999`).
- Workspaces 2001-2003 and scenarios in `tests/fake_account/build.py:1-40`; `extra.py` adds 2006-2014 edge cases (tags, Azure/GCP, mixed tags, uat, eu region, closed, lab) (`tests/fake_account/extra.py:1-14`).
- `tests/fake_account/usage.py` adds table/volume sizes and people to a built Example DB (`tests/fake_account/usage.py:1-9`).
- `tests/test_fake_account.py` builds it in a tmp folder with dbt dev, skips when dbt is missing (`tests/test_fake_account.py:24-41`), then checks named answers (e.g. `test_warehouse_idle_time` `:53`, `test_every_check_has_rows` `:168`).
- Open it in the app: `README.md:671-680`.

## Web tests

- `web/src/components/honesty.test.tsx`, `nav_hash.test.ts`, `roles.test.ts`, `tag_picker.test.ts` (directory listing).
- `npm test` = `vitest run`; `npm run typecheck` = `tsc --noEmit` (`web/package.json:5-10`); jsdom, threads pool (`web/vite.config.ts:40-41`).

## Coverage gate

- `python tools/fixture_coverage.py --check`: every executable id has a grain entry and a `rows(...)` call in `tests/test_findings/`; also duplicate grains and grain/model column drift (`tools/fixture_coverage.py:1-30`). Runs only in the full gate (`tools/gate.py:179-190`).
