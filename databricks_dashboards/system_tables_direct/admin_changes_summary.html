Admin changes, in brief

A two-minute read. Every query, step and column: the detailed guide.

What it is for

Lists admin actions (group membership, groups, admin roles, workspace access, grants and revokes, permissions, cluster policies, settings) with who did them, and whether that was a person or a service principal, to spot manual changes outside automation.

The system tables

System tableWhat it holds
system.access.auditOne row per action in the account: who, when, which workspace, the service and action, the request and its response. Kept for 365 days.
system.access.workspaces_latestEach workspace's id and name.

How it works

  • Group, role, access, grant, permission, policy and setting changes each write a row to system.access.audit, with who made them.
  • A service principal (automation, Terraform) appears as an application id; a person as an email.
  • Rows by a User are changes made by hand: the ones to review.

Example: the same change, by automation or by hand

The query, simplified

The core of it; runs as is in a SQL editor. The dashboard's full queries, step by step: the detailed guide.

-- Admin actions and who did them: a service principal (an application id) or a person (an email).
SELECT event_time, workspace_id, action_name, user_identity.email AS actor,
       CASE WHEN user_identity.email RLIKE '^[0-9a-fA-F-]{36}$' THEN 'Service principal'
            WHEN user_identity.email LIKE '%@%' THEN 'User' ELSE 'Other' END AS actor_type
FROM system.access.audit
WHERE action_name IN ('addPrincipalToGroup', 'removePrincipalFromGroup', 'setAdmin', 'removeAdmin',
                      'updatePermissions', 'changeWorkspaceAcl', 'workspaceConfEdit')   -- part of the list
  AND event_date >= current_date() - 30
ORDER BY event_time DESC;

The rules

TermMeans
Admin actionOne of the service and action names in the list below the Rules.
Actor typeService principal when the actor is a UUID (application id), User when it is an email, else Other (system).
OutcomeDone when the response status is 200, Failed for another status, Unknown when none.

Good to know

  • Only actions still in the audit log (365 days).
  • The action list is from Databricks' audit log reference; an action it doesn't name is not shown.
  • Object or principal reads request_params keys that differ per action; - when none of them is set.
