What this dashboard is for

Shows each workspace: what the catalogs it is home to hold, who uses it, which tables and volumes are used, and who has not been seen for a long time. The app's Workspaces tab as a dashboard.

How the tables join

Grey: system tables. Blue border: a shared check (its steps are listed under Steps). White: steps of the query. Green: the rows the dashboard shows. ◆ marks the columns the joins use.

  1. access.table_lineage → home: most reads and writes
  2. home → held: ON catalog
  3. information_schema → held: COUNT per catalog
  4. table_sizes / volume_sizes (job) → held: SUM bytes, files
  5. access.audit → who: events
  6. query.history → who: queries
  7. held → workspaces, tables, volumes, people: LEFT JOIN ON workspace_id
  8. who → workspaces, tables, volumes, people: LEFT JOIN ON workspace_id
  9. access.table_lineage → workspaces, tables, volumes, people: reads, writes per table

Databricks basics

TermWhat it means
WorkspaceOne Databricks environment (its own URL, users, jobs, clusters). An account holds many workspaces; the dashboards read all of them at once.
Home workspaceThe workspace that reads and writes a catalog most in lineage over 90 days. A catalog's tables and volumes count for that workspace.
Unity Catalog, grantUnity Catalog governs data: catalogs hold schemas, schemas hold tables. A grant gives a principal a privilege on one of them (SELECT, MODIFY, ALL PRIVILEGES, ...); a grant on a catalog or schema reaches everything inside it.
VolumeA Unity Catalog folder for files (CSV, images, exports) inside a schema, under /Volumes/<catalog>/<schema>/<volume>. Its files are not tables, so no system table counts them.
System tablesRead-only tables Databricks fills for the whole account under the catalog system (system.billing, system.lakeflow, system.compute, system.access). The dashboards read them live; there are no tables of our own.
Audit logsystem.access.audit: one row per action someone took (log in, grant, change a group, ...), with who did it, when, in which workspace, the request and whether it succeeded. Databricks keeps it for 365 days.
User, group, service principalA user is a person (an email). A group bundles users. A service principal is a non-human identity for automation (CI/CD, Terraform); in the audit log it appears as its application id, a UUID like 1b2c3d4e-....
Query, CTEA query is SQL. Each one here is a chain of named steps written WITH name AS (...), called CTEs; each step reads the ones before it, and one last SELECT gives the rows.

Rules and thresholds

RuleDefinitionWhy
Home workspaceThe workspace with the most lineage reads and writes of a catalog over 90 days.A catalog shared by many workspaces counts once.
ActiveA person or service principal with an audit event or a query in the workspace in the window.Logins alone miss token users; queries alone miss people browsing.
InactiveNot seen in the workspace for 90+ days within the last year.Candidates for an access review.
Not usedA table or volume with no read or write in the window.Big and unused is the clean-up list.
Complexity indexTables, views, columns, table bytes and volume files, each 0-1 on a log scale against the largest workspace, weighted 25/15/20/25/15, times 100.A rough size of what is held, not a quality score.
Usage indexActive people, service principals and queries the same way, weighted 40/20/40.Bottom right on the scatter: holds a lot, used little.

What it can miss

  • Sizes and volume files come from the sizes job (DESCRIBE DETAIL, a file listing); tables it can't read show no size, with the error in table_sizes.detail.
  • A catalog with no lineage in 90 days has no home workspace: its tables show under No home workspace and count for no workspace.
  • Volume reads and writes depend on the audit log's request_params path; check the keys below.
  • Some system tables only hold workspaces in the same cloud region as the metastore; if a workspace is missing, check its region.

How to read a query

  • No snapshot. Each query reads the Databricks system tables directly, every time the dashboard opens or a filter changes.
  • Widgets share queries. Each widget reads one query and adds up its rows its own way (the Widgets table says how); widgets that read the same query always agree.
  • Each query reads like a recipe: named steps (WITH step AS (...), called CTEs), each building on the one before, then one final SELECT. A step named after a check (for example lakeflow_job_reliability) is a shared, tested check reused unchanged except for the dates; its own steps are listed under it.
  • Time Window: :time_range.min and :time_range.max are the dates picked in the Time Window filter (on Global Filters, or on the page). The end day counts in full.
  • Workspace and the other field filters need no SQL: Databricks keeps the rows whose column matches the pick.
  • $ is list price (usage x the SKU's list price), not the invoice.
  • Comments in the SQL (green, starting --) are added on this page only.

The queries

Workspaces: what each holds and how much it is used

Shows: One row per workspace: tables, views, columns, volumes, files and size of the catalogs it is home to; people, service principals and queries in the window; and the two indexes. Used by: The Table usage page and the scatter.

Why it is built this way: One row per workspace with what it holds and how much it is used, plus the scatter. Each catalog counts once, for its home workspace; logs keep one large workspace from flattening the others.

How its tables join

Grey: system tables. Blue border: a shared check (its steps are listed under Steps). White: steps of the query. Green: the rows the dashboard shows. ◆ marks the columns the joins use.

    1. System tables it reads

    • system.access.audit
    • system.access.table_lineage
    • system.access.workspaces_latest
    • system.information_schema.catalogs
    • system.information_schema.columns
    • system.information_schema.tables
    • system.information_schema.volumes
    • system.query.history

    2. Steps (CTEs), in order

    1. wsl: Workspace id to name and URL.
      Its SQL (6 lines)
      -- Workspaces: what each holds and how much it is used. Dates from the Time Window.
-- Workspace id to name and URL.
wsl AS (
  SELECT CAST(workspace_id AS STRING) AS workspace_id, workspace_name, workspace_url
  FROM system.access.workspaces_latest
)
    2. seen: Lineage reads and writes per catalog and workspace over 90 days.
      Its SQL (10 lines)
      -- Lineage reads and writes per catalog and workspace over 90 days.
seen AS (
  SELECT catalog, CAST(workspace_id AS STRING) AS workspace_id, COUNT(*) AS events FROM (
    SELECT workspace_id, source_table_catalog AS catalog FROM system.access.table_lineage
    WHERE event_date >= date_sub(date_add(:time_range.max, 1), 90) AND event_date < date_add(:time_range.max, 1)
    UNION ALL
    SELECT workspace_id, target_table_catalog FROM system.access.table_lineage
    WHERE event_date >= date_sub(date_add(:time_range.max, 1), 90) AND event_date < date_add(:time_range.max, 1)
  ) WHERE catalog IS NOT NULL GROUP BY 1, 2
)
    3. home: Each catalog's home workspace: the one with the most of them.
      Its SQL (7 lines)
      -- Each catalog's home workspace: the one with the most of them.
home AS (
  SELECT c.catalog_name AS catalog, max_by(s.workspace_id, s.events) AS workspace_id
  FROM system.information_schema.catalogs c LEFT JOIN seen s ON s.catalog = c.catalog_name
  WHERE c.catalog_name NOT IN ('system', 'samples', '__databricks_internal')
  GROUP BY c.catalog_name
)
    4. place: Each catalog with its home workspace's name.
      Its SQL (7 lines)
      -- Each catalog with its home workspace's name.
place AS (
  -- a catalog without lineage in 90 days keeps its rows, under No home workspace
  SELECT h.catalog, h.workspace_id,
         COALESCE(w.workspace_name, h.workspace_id, 'No home workspace') AS workspace
  FROM home h LEFT JOIN wsl w ON w.workspace_id = h.workspace_id
)
    5. cols: Columns per table and view.
      Its SQL (5 lines)
      -- Columns per table and view.
cols AS (
  SELECT table_catalog, table_schema, table_name, COUNT(*) AS n FROM system.information_schema.columns
  WHERE table_schema <> 'information_schema' GROUP BY 1, 2, 3
)
    6. held: Per workspace: catalogs, tables, views and columns of the catalogs it is home to.
      Its SQL (11 lines)
      -- Per workspace: catalogs, tables, views and columns of the catalogs it is home to.
held AS (
  SELECT p.workspace_id, COUNT(DISTINCT p.catalog) AS catalogs,
         COUNT_IF(t.table_type <> 'VIEW') AS tables, COUNT_IF(t.table_type = 'VIEW') AS views,
         COALESCE(SUM(c.n), 0) AS columns
  FROM place p
  LEFT JOIN system.information_schema.tables t ON t.table_catalog = p.catalog AND t.table_schema <> 'information_schema'
  LEFT JOIN cols c ON c.table_catalog = t.table_catalog AND c.table_schema = t.table_schema AND c.table_name = t.table_name
  WHERE p.workspace_id IS NOT NULL
  GROUP BY 1
)
    7. vols: Per workspace: volumes, and their files and bytes from the job's volume_sizes.
      Its SQL (11 lines)
      -- Per workspace: volumes, and their files and bytes from the job's volume_sizes.
vols AS (
  SELECT p.workspace_id, COUNT(*) AS volumes, COALESCE(SUM(vs.files), 0) AS volume_files,
         COALESCE(SUM(vs.size_in_bytes), 0) AS volume_bytes
  FROM system.information_schema.volumes v
  JOIN place p ON p.catalog = v.volume_catalog
  LEFT JOIN main.workspace_data.volume_sizes vs
    ON vs.catalog = v.volume_catalog AND vs.schema = v.volume_schema AND vs.volume_name = v.volume_name
  WHERE p.workspace_id IS NOT NULL
  GROUP BY 1
)
    8. sizes: Per workspace: bytes of its tables, from the job's table_sizes (DESCRIBE DETAIL).
      Its SQL (7 lines)
      -- Per workspace: bytes of its tables, from the job's table_sizes (DESCRIBE DETAIL).
sizes AS (
  SELECT p.workspace_id, SUM(s.size_in_bytes) AS table_bytes
  FROM main.workspace_data.table_sizes s JOIN place p ON p.catalog = s.catalog
  WHERE p.workspace_id IS NOT NULL
  GROUP BY 1
)
    9. aud: Audit events per workspace and identity in the window: last event and successful logins.
      Its SQL (10 lines)
      -- Audit events per workspace and identity in the window: last event and successful logins.
aud AS (
  SELECT CAST(workspace_id AS STRING) AS workspace_id,
         lower(COALESCE(user_identity.email, user_identity.subject_name)) AS who,
         MAX(event_time) AS last_event,
         COUNT_IF(service_name = 'accounts' AND action_name RLIKE '(?i)login' AND response.status_code = 200) AS logins
  FROM system.access.audit
  WHERE event_date >= CAST(:time_range.min AS DATE) AND event_date < date_add(:time_range.max, 1)
  GROUP BY 1, 2
)
    10. qh: Queries per workspace and identity in the window.
      Its SQL (8 lines)
      -- Queries per workspace and identity in the window.
qh AS (
  SELECT CAST(workspace_id AS STRING) AS workspace_id, lower(executed_by) AS who,
         COUNT(*) AS queries, MAX(start_time) AS last_query
  FROM system.query.history
  WHERE start_time >= CAST(:time_range.min AS DATE) AND start_time < date_add(:time_range.max, 1)
  GROUP BY 1, 2
)
    11. who: Both together: one row per workspace and identity, a person (email) or a service principal (UUID).
      Its SQL (9 lines)
      -- Both together: one row per workspace and identity, a person (email) or a service principal (UUID).
who AS (
  SELECT COALESCE(a.workspace_id, q.workspace_id) AS workspace_id, COALESCE(a.who, q.who) AS who,
         COALESCE(a.logins, 0) AS logins, COALESCE(q.queries, 0) AS queries,
         GREATEST(a.last_event, q.last_query) AS last_seen,
         CASE WHEN COALESCE(a.who, q.who) RLIKE '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' THEN 'Service principal'
              WHEN COALESCE(a.who, q.who) LIKE '%@%' THEN 'Person' ELSE 'Other' END AS kind
  FROM aud a FULL OUTER JOIN qh q ON q.workspace_id = a.workspace_id AND q.who = a.who
)
    12. act: Per workspace: active people, service principals, queries and the last activity.
      Its SQL (7 lines)
      -- Per workspace: active people, service principals, queries and the last activity.
act AS (
  SELECT workspace_id, COUNT(DISTINCT CASE WHEN kind = 'Person' THEN who END) AS active_people,
         COUNT(DISTINCT CASE WHEN kind = 'Service principal' THEN who END) AS active_service_principals,
         SUM(queries) AS queries, MAX(last_seen) AS last_activity
  FROM who GROUP BY 1
)
    13. ids: Every workspace with activity or a catalog.
      Its SQL (4 lines)
      -- Every workspace with activity or a catalog.
ids AS (
  SELECT workspace_id FROM act UNION SELECT workspace_id FROM held
)
    14. base: Everything per workspace; a missing count reads 0.
      Its SQL (17 lines)
      -- Everything per workspace; a missing count reads 0.
base AS (
  SELECT i.workspace_id, COALESCE(w.workspace_name, i.workspace_id) AS workspace, w.workspace_url,
         COALESCE(h.catalogs, 0) AS catalogs, COALESCE(h.tables, 0) AS tables, COALESCE(h.views, 0) AS views,
         COALESCE(h.columns, 0) AS columns, COALESCE(v.volumes, 0) AS volumes,
         COALESCE(v.volume_files, 0) AS volume_files, COALESCE(s.table_bytes, 0) AS table_bytes,
         COALESCE(s.table_bytes, 0) + COALESCE(v.volume_bytes, 0) AS data_bytes,
         COALESCE(a.active_people, 0) AS active_people, COALESCE(a.active_service_principals, 0) AS active_service_principals,
         COALESCE(a.queries, 0) AS queries, a.last_activity
  FROM ids i
  LEFT JOIN held h ON h.workspace_id = i.workspace_id
  LEFT JOIN vols v ON v.workspace_id = i.workspace_id
  LEFT JOIN sizes s ON s.workspace_id = i.workspace_id
  LEFT JOIN act a ON a.workspace_id = i.workspace_id
  LEFT JOIN wsl w ON w.workspace_id = i.workspace_id
  WHERE i.workspace_id IS NOT NULL AND i.workspace_id <> '0'
)

    One row per workspace, most used first.

  SELECT workspace_id, COUNT(DISTINCT CASE WHEN kind = 'Person' THEN who END) AS active_people,
         COUNT(DISTINCT CASE WHEN kind = 'Service principal' THEN who END) AS active_service_principals,
         SUM(queries) AS queries, MAX(last_seen) AS last_activity
  FROM who GROUP BY 1
),
-- Every workspace with activity or a catalog.
ids AS (
  SELECT workspace_id FROM act UNION SELECT workspace_id FROM held
),
-- Everything per workspace; a missing count reads 0.
base AS (
  SELECT i.workspace_id, COALESCE(w.workspace_name, i.workspace_id) AS workspace, w.workspace_url,
         COALESCE(h.catalogs, 0) AS catalogs, COALESCE(h.tables, 0) AS tables, COALESCE(h.views, 0) AS views,
         COALESCE(h.columns, 0) AS columns, COALESCE(v.volumes, 0) AS volumes,
         COALESCE(v.volume_files, 0) AS volume_files, COALESCE(s.table_bytes, 0) AS table_bytes,
         COALESCE(s.table_bytes, 0) + COALESCE(v.volume_bytes, 0) AS data_bytes,
         COALESCE(a.active_people, 0) AS active_people, COALESCE(a.active_service_principals, 0) AS active_service_principals,
         COALESCE(a.queries, 0) AS queries, a.last_activity
  FROM ids i
  LEFT JOIN held h ON h.workspace_id = i.workspace_id
  LEFT JOIN vols v ON v.workspace_id = i.workspace_id
  LEFT JOIN sizes s ON s.workspace_id = i.workspace_id
  LEFT JOIN act a ON a.workspace_id = i.workspace_id
  LEFT JOIN wsl w ON w.workspace_id = i.workspace_id
  WHERE i.workspace_id IS NOT NULL AND i.workspace_id <> '0'
)
-- Final SELECT: the rows the widgets read.
SELECT workspace, workspace_id,
       concat('https://', regexp_replace(regexp_replace(COALESCE(workspace_url, ''), '^https?://', ''), '/.*$', '')) AS workspace_link,
       catalogs, tables, views, columns, volumes, volume_files, table_bytes, data_bytes,
       ROUND(data_bytes / 1073741824.0, 2) AS data_gb,
       active_people, active_service_principals, queries, CAST(last_activity AS STRING) AS last_activity,
       COALESCE(ROUND(100 * (0.25 * COALESCE(ln(1 + tables) / NULLIF(MAX(ln(1 + tables)) OVER (), 0), 0) + 0.15 * COALESCE(ln(1 + views) / NULLIF(MAX(ln(1 + views)) OVER (), 0), 0) + 0.2 * COALESCE(ln(1 + columns) / NULLIF(MAX(ln(1 + columns)) OVER (), 0), 0) + 0.25 * COALESCE(ln(1 + table_bytes) / NULLIF(MAX(ln(1 + table_bytes)) OVER (), 0), 0) + 0.15 * COALESCE(ln(1 + volume_files) / NULLIF(MAX(ln(1 + volume_files)) OVER (), 0), 0)) / NULLIF(CASE WHEN MAX(tables) OVER () > 0 THEN 0.25 ELSE 0 END + CASE WHEN MAX(views) OVER () > 0 THEN 0.15 ELSE 0 END + CASE WHEN MAX(columns) OVER () > 0 THEN 0.2 ELSE 0 END + CASE WHEN MAX(table_bytes) OVER () > 0 THEN 0.25 ELSE 0 END + CASE WHEN MAX(volume_files) OVER () > 0 THEN 0.15 ELSE 0 END, 0), 1), 0) AS complexity_index,
       COALESCE(ROUND(100 * (0.4 * COALESCE(ln(1 + active_people) / NULLIF(MAX(ln(1 + active_people)) OVER (), 0), 0) + 0.2 * COALESCE(ln(1 + active_service_principals) / NULLIF(MAX(ln(1 + active_service_principals)) OVER (), 0), 0) + 0.4 * COALESCE(ln(1 + queries) / NULLIF(MAX(ln(1 + queries)) OVER (), 0), 0)) / NULLIF(CASE WHEN MAX(active_people) OVER () > 0 THEN 0.4 ELSE 0 END + CASE WHEN MAX(active_service_principals) OVER () > 0 THEN 0.2 ELSE 0 END + CASE WHEN MAX(queries) OVER () > 0 THEN 0.4 ELSE 0 END, 0), 1), 0) AS usage_index, 1 AS workspaces
FROM base
ORDER BY usage_index DESC, workspace

    Tables and views: size, last read and write

         volume_catalog || '.' || volume_schema || '.' || volume_name AS full_name
  FROM system.information_schema.volumes WHERE volume_catalog NOT IN ('system', 'samples', '__databricks_internal')
),
-- File-system events under /Volumes in the window: who, when, read or write.
ev AS (
  SELECT regexp_extract(COALESCE(request_params['path'], request_params['file_path'], request_params['directory_path']),
                        '^/Volumes/([^/]+)/([^/]+)/([^/]+)', 0) AS path_root,
         lower(COALESCE(user_identity.email, user_identity.subject_name)) AS who, event_time,
         action_name RLIKE '(?i)put|upload|create|delete|write|mkdir' AS is_write
  FROM system.access.audit
  WHERE event_date >= CAST(:time_range.min AS DATE) AND event_date < date_add(:time_range.max, 1) AND service_name = 'filesystem' AND response.status_code = 200
),
-- Per volume: reads, writes, users and the last access.
used AS (
  SELECT replace(substr(path_root, 10), '/', '.') AS full_name, COUNT_IF(NOT is_write) AS reads, COUNT_IF(is_write) AS writes,
         COUNT(DISTINCT who) AS users, MAX(event_time) AS last_access
  FROM ev WHERE path_root <> '' GROUP BY 1
)
-- Final SELECT: the rows the widgets read.
SELECT p.workspace, v.catalog, v.sch AS schema_name, v.full_name AS volume, lower(v.volume_type) AS volume_type,
       vs.files, vs.size_in_bytes, ROUND(vs.size_in_bytes / 1073741824.0, 2) AS size_gb,
       COALESCE(u.reads, 0) AS reads, COALESCE(u.writes, 0) AS writes, COALESCE(u.users, 0) AS users,
       CAST(u.last_access AS STRING) AS last_access,
       CASE WHEN COALESCE(u.reads, 0) + COALESCE(u.writes, 0) > 0 THEN 'Used' ELSE 'Not used' END AS use, 1 AS volumes
FROM v
LEFT JOIN place p ON p.catalog = v.catalog
LEFT JOIN main.workspace_data.volume_sizes vs ON vs.catalog = v.catalog AND vs.schema = v.sch AND vs.volume_name = v.volume_name
LEFT JOIN used u ON u.full_name = v.full_name
ORDER BY vs.size_in_bytes DESC NULLS LAST, v.full_name

        People and service principals: activity and last seen

        Shows: Everyone with an audit event in a workspace over the last year: activity in the window, last seen, and inactive when not seen for 90+ days. Used by: The User activity page.

        Why it is built this way: Active users answer who works there; a year of audit answers who stopped, for access reviews.

        How its tables join

        Grey: system tables. Blue border: a shared check (its steps are listed under Steps). White: steps of the query. Green: the rows the dashboard shows. ◆ marks the columns the joins use.

          1. System tables it reads

          • system.access.audit
          • system.access.workspaces_latest
          • system.query.history

          2. Steps (CTEs), in order

            Its SQL (5 lines)

)
          2. aud: Audit events per workspace and identity in the window: last event and successful logins.
            Its SQL (10 lines)
            -- Audit events per workspace and identity in the window: last event and successful logins.
aud AS (

  GROUP BY 1, 2

          4. who: Both together, with the kind: a person (email) or a service principal (UUID).
            Its SQL (9 lines)
            -- Both together, with the kind: a person (email) or a service principal (UUID).
who AS (
  SELECT COALESCE(a.workspace_id, q.workspace_id) AS workspace_id, COALESCE(a.who, q.who) AS who,
         COALESCE(a.logins, 0) AS logins, COALESCE(q.queries, 0) AS queries,
         GREATEST(a.last_event, q.last_query) AS last_seen,
         CASE WHEN COALESCE(a.who, q.who) RLIKE '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' THEN 'Service principal'
              WHEN COALESCE(a.who, q.who) LIKE '%@%' THEN 'Person' ELSE 'Other' END AS kind

          -- People and service principals: activity and last seen. Dates from the Time Window; last seen over a year.
-- Workspace id to name.
WITH wsl AS (
  SELECT CAST(workspace_id AS STRING) AS workspace_id, workspace_name FROM system.access.workspaces_latest
),
-- Audit events per workspace and identity in the window: last event and successful logins.
aud AS (
  SELECT CAST(workspace_id AS STRING) AS workspace_id,
         lower(COALESCE(user_identity.email, user_identity.subject_name)) AS who,
         MAX(event_time) AS last_event,
         COUNT_IF(service_name = 'accounts' AND action_name RLIKE '(?i)login' AND response.status_code = 200) AS logins
  FROM system.access.audit
  WHERE event_date >= CAST(:time_range.min AS DATE) AND event_date < date_add(:time_range.max, 1)
  GROUP BY 1, 2
),
-- Queries per workspace and identity in the window.
qh AS (
  SELECT CAST(workspace_id AS STRING) AS workspace_id, lower(executed_by) AS who,
         COUNT(*) AS queries, MAX(start_time) AS last_query
  FROM system.query.history
  WHERE start_time >= CAST(:time_range.min AS DATE) AND start_time < date_add(:time_range.max, 1)
  GROUP BY 1, 2
),
-- Both together, with the kind: a person (email) or a service principal (UUID).
who AS (
  SELECT COALESCE(a.workspace_id, q.workspace_id) AS workspace_id, COALESCE(a.who, q.who) AS who,
         COALESCE(a.logins, 0) AS logins, COALESCE(q.queries, 0) AS queries,
         GREATEST(a.last_event, q.last_query) AS last_seen,
         CASE WHEN COALESCE(a.who, q.who) RLIKE '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' THEN 'Service principal'
              WHEN COALESCE(a.who, q.who) LIKE '%@%' THEN 'Person' ELSE 'Other' END AS kind
  FROM aud a FULL OUTER JOIN qh q ON q.workspace_id = a.workspace_id AND q.who = a.who
),
-- Each identity's last audit event per workspace over the last year.
year AS (
  SELECT CAST(workspace_id AS STRING) AS workspace_id, lower(COALESCE(user_identity.email, user_identity.subject_name)) AS who,
         MAX(event_date) AS last_seen_year
  FROM system.access.audit
  WHERE event_date >= date_sub(date_add(:time_range.max, 1), 365) AND event_date < date_add(:time_range.max, 1)
  GROUP BY 1, 2
),
-- Last seen in the year joined to the window's activity.
k AS (
  SELECT y.workspace_id, y.who, y.last_seen_year, w.logins, w.queries, w.last_seen,
         CASE WHEN y.who RLIKE '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' THEN 'Service principal' WHEN y.who LIKE '%@%' THEN 'Person' ELSE 'Other' END AS kind
  FROM year y LEFT JOIN who w ON w.workspace_id = y.workspace_id AND w.who = y.who
)
-- Final SELECT: the rows the widgets read.
SELECT COALESCE(n.workspace_name, k.workspace_id) AS workspace, k.who AS identity, k.kind,
       COALESCE(k.logins, 0) AS logins, COALESCE(k.queries, 0) AS queries,
       CAST(COALESCE(k.last_seen, k.last_seen_year) AS STRING) AS last_seen,
       datediff(date_add(:time_range.max, 1), CAST(k.last_seen_year AS DATE)) AS days_since,
       CASE WHEN datediff(date_add(:time_range.max, 1), CAST(k.last_seen_year AS DATE)) < 30 THEN '1 under 30 days'
            WHEN datediff(date_add(:time_range.max, 1), CAST(k.last_seen_year AS DATE)) < 90 THEN '2 30-90 days'
            WHEN datediff(date_add(:time_range.max, 1), CAST(k.last_seen_year AS DATE)) < 180 THEN '3 90-180 days'
            ELSE '4 180+ days' END AS last_seen_band,
       CASE WHEN datediff(date_add(:time_range.max, 1), CAST(k.last_seen_year AS DATE)) >= 90 THEN 1 ELSE 0 END AS inactive,
       CASE WHEN COALESCE(k.logins, 0) + COALESCE(k.queries, 0) > 0 THEN 1 ELSE 0 END AS active, 1 AS identities
FROM k
LEFT JOIN wsl n ON n.workspace_id = k.workspace_id
WHERE k.kind <> 'Other' AND k.workspace_id IS NOT NULL AND k.workspace_id <> '0'
ORDER BY days_since DESC, identity
