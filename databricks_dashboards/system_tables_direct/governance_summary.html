Governance, in brief

A two-minute read. Every query, step and column: the detailed guide.

What it is for

One governance dashboard over system.access: broad grants, admin changes by hand, outbound requests a network policy blocked and workspace use, each on its own tab, with an Overview of their headline numbers and a tab showing the dashboard's own load from its query tags.

How the tables join

Grey: system tables. Blue border: a shared check (its steps are listed under Steps). White: steps of the query. Green: the rows the dashboard shows. ◆ marks the columns the joins use.

  1. access.audit → one query per tab: grants, admin actions, logins, last activity
  2. access.outbound_network → one query per tab: denied requests
  3. query.history → one query per tab: query_tags dashboard = governance
  4. access.workspaces_latest → one query per tab: JOIN ON workspace_id: names
  5. one query per tab → Overview and tabs: Overview counts the same queries

    The system tables

    System tableWhat it holds
    system.access.auditOne row per action in the account: who, when, which workspace, the service and action, the request and its response. Kept for 365 days.
    system.access.outbound_network
    system.access.workspaces_latestEach workspace's id and name.
    system.compute.warehousesEach SQL warehouse's settings over time: size, type, auto-stop minutes.
    system.query.historyEvery SQL statement: who ran it, on which warehouse, start, end, status, bytes read.

    How it works

    • Grants, admin changes and logins each write a row to system.access.audit; refused outbound requests from serverless compute write one to system.access.outbound_network.
    • Each tab reads them live; the Overview counts the same queries, so its tiles and the tabs agree.
    • Every query is tagged with the dashboard and its tab, so Dashboard load finds its own queries in system.query.history.

    The query, simplified

    The core of it; runs as is in a SQL editor. The dashboard's full queries, step by step: the detailed guide.

    -- Per tab, its headline number over the last 30 days.
SELECT 'Admin changes by people' AS tile, COUNT(*) AS value
FROM system.access.audit
WHERE action_name IN ('addPrincipalToGroup', 'removePrincipalFromGroup', 'setAdmin', 'updatePermissions')
  AND user_identity.email LIKE '%@%' AND event_date >= current_date() - 30
UNION ALL
SELECT 'Blocked outbound requests', COUNT(*)
FROM system.access.outbound_network
WHERE upper(access_type) <> 'DRY_RUN_DENIAL' AND event_time >= current_date() - 30
UNION ALL
SELECT 'Queries of this dashboard', COUNT(*)
FROM system.query.history
WHERE query_tags['dashboard'] = 'governance' AND query_tags['tab'] IS NOT NULL
  AND statement_type <> 'SET' AND start_time >= current_date() - 30;

    The pages

    PageWhat it shows
    OverviewGrants, admin changes, network denials and workspace use across the account, from system.access. Each tile is the headline of its tab.
    Broad grantsEvery privilege granted in Unity Catalog, from the audit log. Critical: ALL PRIVILEGES on a catalog, schema or table, or anything granted to account users.
    Admin changesWho changed groups, admin roles, workspace access, grants, permissions, cluster policies and settings. In an IaC platform these come from service principals; a person is a manual change.
    NetworkOutbound requests from serverless compute that a network policy blocked, from system.access.outbound_network. Dry run: logged, not blocked.
    Workspace usageActive users per class and workspace in the picked month, and workspaces with no activity for 90+ days. The Month filter sets only the active users.
    Dashboard loadThis dashboard's own queries, found by their query tags (dashboard = governance, tab = the page): how many, how long and on which warehouse.

    The rules

    TermMeans
    CriticalALL_PRIVILEGES on a CATALOG, SCHEMA or TABLE, or any privilege to account users.
    Actor typeService principal when the actor is a UUID (application id), User when it is an email, else Other (system).
    BlockedAn outbound_network row whose access type is not DRY_RUN_DENIAL (nor ALLOW..., with extended logs).
    InactiveNo audit event for 90+ days.
    Dashboard queryA query-history row with query_tags dashboard = governance and a tab, not a SET statement.

    Good to know

    • Only events still in the audit log (365 days).
    • outbound_network holds serverless egress only, and only where a network policy is set; no policy, no rows.
    • Dashboard load counts queries and run time, not $: the warehouse's bill covers every query it ran.
