# Dashboards on system tables, direct

These AI/BI dashboards read `system.*` live: no snapshot notebook, no tables of our own (except
Workspace data's sizes, below). Every opening re-runs the checks for the picked **Time Window** (Global
Filters; default the last 30 days, excluding today).

| File | Pages |
| --- | --- |
| `waste_savings.lvdash.json` | Possible waste, Warehouses, Auto-stop what-if, Clusters & pools, Failed runs & queries, Serving endpoints, Flagged, not priced, Global Filters |
| `jobs_health.lvdash.json` | Failed jobs, Failed job details, Slow jobs, Hygiene, Job size, Pipelines, Global Filters |
| `workspace_usage.lvdash.json` | Workspace usage: active users per class and workspace, inactive workspaces (Month, Class, Workspace filters on the page) |
| `broad_grants.lvdash.json` | Broad grants: UC grants from the audit log, ALL PRIVILEGES and account users flagged (filters on the page) |
| `admin_changes.lvdash.json` | Admin changes: who changed groups, roles, access, grants and settings, person or service principal (filters on the page) |
| `workspace_data.lvdash.json` | Table usage, Volume usage, User activity: one row per workspace (what its home catalogs hold, complexity, usage), tables and volumes by last read, inactive users |
| `workspace_data_sizes.py` | The notebook that fills its size tables; run it daily as a job |
| `<name>.html` | Every query of that dashboard, step by step, for new readers |

- Generated by `tools/build_direct_dashboards.py` from the app's checks (`app/direct_sql`) and a few
  queries of its own; regenerate rather than hand-edit. Thresholds (flaky, slow run, inactive) sit
  at the top of `tools/direct_jobs_health.py` and `tools/direct_governance.py`.
- **Query tags:** `--query-tags domain=observability,cost_center=platform` replaces the settings'
  `query_tags` (letters, digits and `_` only); `dashboard` and `tab` are always added.
- **Workspace classes** (Workspace usage): `--workspace-class CLASS=pattern`, once per class, a `LIKE`
  pattern on the lower-case workspace name; the first match wins, the rest read Not classified.
- **Workspace data sizes:** sizes and volume files aren't in any system table, so
  `workspace_data_sizes.py` writes `table_sizes`, `table_history` and `volume_sizes` (`DESCRIBE DETAIL`,
  `DESCRIBE HISTORY`, a volume listing) for every catalog it can read.
  - `--sizes-schema <catalog>.<schema>` (default `main.workspace_data`): where they go. Create it first.
  - The job needs `USE CATALOG`, `USE SCHEMA`, `SELECT` and `READ VOLUME` on the catalogs (`BROWSE` isn't
    enough) and `CREATE TABLE`, `MODIFY` on that schema.
  - A catalog counts for its home workspace: the one that reads and writes it most in lineage.
- For the bundle in `databricks-observability`: build with its tags and classes into a scratch
  folder, then copy the `.lvdash.json` to its `src/` and the `.html` to its `docs/queries/`.
- Import: **Dashboards** › **Import dashboard from file**, then pick a SQL warehouse.
- Viewers need `SELECT` on the system tables, or publish with **Embed credentials** on.
- Slower than the Lakehouse Health set: each page re-runs its checks every time it opens. Workspace
  usage reads up to a year of `system.access.audit` for the last activity.
