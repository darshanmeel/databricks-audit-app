What this dashboard is for

Shows what the dashboards of this set cost to run: their queries per dashboard, tab, day and warehouse, with failures, cache hits, run time, queue time and an estimated $, found by their query tags.

Databricks basics

TermWhat it means
System tablesRead-only tables Databricks fills for the whole account under the catalog system (system.billing, system.lakeflow, system.compute, system.access). The dashboards read them live; there are no tables of our own.
SQL warehouseCompute for SQL: dashboards, BI tools and the SQL editor run their queries on it. It is billed while it runs, whether or not a query is running, and stops after its auto-stop setting with no query. Serverless warehouses start in seconds; pro and classic take minutes.
Query tagsKey-value labels set with SET QUERY_TAGS at the top of a query and stored with it in system.query.history (query_tags). Every dataset here sets dashboard and tab.
User, group, service principalA user is a person (an email). A group bundles users. A service principal is a non-human identity for automation (CI/CD, Terraform); in the audit log it appears as its application id, a UUID like 1b2c3d4e-....
Query, CTEA query is SQL. Each one here is a chain of named steps written WITH name AS (...), called CTEs; each step reads the ones before it, and one last SELECT gives the rows.

Rules and thresholds

RuleDefinitionWhy
Dashboard queryA query-history row whose dashboard tag is one of this set's dashboards and that has a tab tag; SET statements left out.The SET QUERY_TAGS lines run as statements of their own but do no work.
Queuedwaiting_at_capacity_duration_ms: the query waited because the warehouse was full.Queue time on a dashboard means a bigger or a scaling warehouse, or fewer widgets per page.
From cachefrom_result_cache is true.A repeat view answered without compute.
Estimated $The warehouse's list-price bill in the hour the query started, times the query's task time over all task time on that warehouse in that hour.A warehouse bills for every query and its idle time; sharing the hour by work gives each dashboard its part.

What it can miss

  • Estimated $ is list price, not the invoice, and shares idle time by work: a dashboard alone on a warehouse carries all of it. A query spanning hours is priced in its start hour.
  • Only queries since the dashboards carry tags; an older copy without SET QUERY_TAGS doesn't show.
  • A dashboard renamed or added later shows only after this dashboard is rebuilt.
  • Some system tables only hold workspaces in the same cloud region as the metastore; if a workspace is missing, check its region.

Which dashboard tags your query history has

SELECT query_tags['dashboard'] AS dashboard, query_tags['tab'] AS tab, COUNT(*) AS queries
FROM system.query.history
WHERE query_tags['dashboard'] IS NOT NULL AND statement_type <> 'SET'
  AND start_time >= current_date() - 7
GROUP BY 1, 2 ORDER BY 3 DESC;

How to read a query

  • No snapshot. Each query reads the Databricks system tables directly, every time the dashboard opens or a filter changes.
  • Widgets share queries. Each widget reads one query and adds up its rows its own way (the Widgets table says how); widgets that read the same query always agree.
  • Each query reads like a recipe: named steps (WITH step AS (...), called CTEs), each building on the one before, then one final SELECT. A step named after a check (for example lakeflow_job_reliability) is a shared, tested check reused unchanged except for the dates; its own steps are listed under it.
  • Time Window: :time_range.min and :time_range.max are the dates picked in the Time Window filter (on Global Filters, or on the page). The end day counts in full.
  • Workspace and the other field filters need no SQL: Databricks keeps the rows whose column matches the pick.
  • $ is list price (usage x the SKU's list price), not the invoice.
  • Comments in the SQL (green, starting --) are added on this page only.

The queries

Dashboard load: the queries of every dashboard in this set, per tab, from their query tags

Shows: Every query of the dashboards in this set, found by their dashboard and tab query tags, per dashboard, tab, day, identity and warehouse: count, failures, cache hits, run time, queue time, data read and estimated $. Used by: The whole dashboard.

Why it is built this way: A dashboard's query text reads <REDACTED> in the query history, so only its tags tell its queries apart. Per dashboard and tab it shows which page is slow, fails or queues, and which warehouse carries the load.

2. Steps (CTEs), in order

  1. wh: Warehouse id to name: the latest row per warehouse.
    Its SQL (6 lines)
    -- Dashboard load: the queries of every dashboard in this set, per tab, from their query tags. List price; dates from the Time Window.
-- Warehouse id to name: the latest row per warehouse.
wh AS (
  SELECT CAST(warehouse_id AS STRING) AS warehouse_id, warehouse_name FROM system.compute.warehouses
  QUALIFY ROW_NUMBER() OVER (PARTITION BY warehouse_id ORDER BY change_time DESC) = 1
)
  2. boards: The dashboards of this set: their dashboard tag value and title.
    Its SQL (26 lines)
    -- The dashboards of this set: their dashboard tag value and title.
boards AS (
  SELECT * FROM VALUES
         ('lakehouse_health_01_overview', 'Lakehouse Health 01 - Overview'),
         ('lakehouse_health_02_actions', 'Lakehouse Health 02 - Actions'),
         ('lakehouse_health_03_jobs', 'Lakehouse Health 03 - Jobs'),
         ('lakehouse_health_04_compute', 'Lakehouse Health 04 - Compute'),
         ('lakehouse_health_05_queries', 'Lakehouse Health 05 - Queries'),
         ('lakehouse_health_06_cost', 'Lakehouse Health 06 - Cost'),
         ('lakehouse_health_07_waste_savings', 'Lakehouse Health 07 - Waste & savings'),
         ('lakehouse_health_08_ml_ai', 'Lakehouse Health 08 - ML & AI'),
         ('lakehouse_health_09_genie', 'Lakehouse Health 09 - Genie'),
         ('lakehouse_health_10_governance_pii', 'Lakehouse Health 10 - Governance & PII'),
         ('lakehouse_health_11_storage', 'Lakehouse Health 11 - Storage'),
         ('lakehouse_health_12_tags', 'Lakehouse Health 12 - Tags'),
         ('lakehouse_health_13_all_findings', 'Lakehouse Health 13 - All findings'),
         ('lakehouse_health_14_coverage_gaps', 'Lakehouse Health 14 - Coverage & Gaps'),
         ('waste_savings', 'Waste & savings'),
         ('jobs_health', 'Jobs health'),
         ('workspace_usage', 'Workspace usage'),
         ('broad_grants', 'Broad grants'),
         ('admin_changes', 'Admin changes'),
         ('data_usage', 'Data usage'),
         ('dashboard_load', 'Dashboard load')
         AS t(slug, dashboard)
)
  3. q: Their queries in the window, tagged with a dashboard and a tab; SET statements left out.
    Its SQL (16 lines)
    -- Their queries in the window, tagged with a dashboard and a tab; SET statements left out.
q AS (
  SELECT query_tags['dashboard'] AS slug, query_tags['tab'] AS tab, CAST(start_time AS DATE) AS day,
         date_trunc('HOUR', start_time) AS hr,
         executed_by, CAST(compute.warehouse_id AS STRING) AS warehouse_id, execution_status,
         COALESCE(from_result_cache, false) AS cached,
         COALESCE(total_duration_ms, 0) AS duration_ms,
         CASE WHEN from_result_cache THEN 0
              ELSE COALESCE(total_task_duration_ms, execution_duration_ms, total_duration_ms, 0) END AS weight_ms,
         COALESCE(waiting_at_capacity_duration_ms, 0) AS queued_ms, COALESCE(read_bytes, 0) AS read_bytes
  FROM system.query.history
  -- the SET QUERY_TAGS statements are not the dashboard's work; on a reused session they carry a tab
  WHERE query_tags['dashboard'] IS NOT NULL AND query_tags['tab'] IS NOT NULL
    AND upper(COALESCE(statement_type, '')) <> 'SET'
    AND start_time >= CAST(:time_range.min AS DATE) AND start_time < date_add(:time_range.max, 1)
)
  4. all_work: Everything those warehouses ran per hour, by task time; a cached result counts 0.
    Its SQL (11 lines)
    -- Everything those warehouses ran per hour, by task time; a cached result counts 0.
all_work AS (
  -- everything those warehouses ran per hour: a query's $ is its share of the hour's work
  SELECT CAST(compute.warehouse_id AS STRING) AS warehouse_id, date_trunc('HOUR', start_time) AS hr,
         SUM(CASE WHEN from_result_cache THEN 0
                  ELSE COALESCE(total_task_duration_ms, execution_duration_ms, total_duration_ms, 0) END) AS all_ms
  FROM system.query.history
  WHERE start_time >= CAST(:time_range.min AS DATE) AND start_time < date_add(:time_range.max, 1)
    AND CAST(compute.warehouse_id AS STRING) IN (SELECT warehouse_id FROM q)
  GROUP BY 1, 2
)
  5. price: List price of every SKU over time.
    Its SQL (7 lines)
    -- List price of every SKU over time.
price AS (
  SELECT sku_name, cloud, usage_unit, price_start_time, price_end_time,
         CAST(pricing.effective_list.default AS DOUBLE) AS list_rate
  FROM system.billing.list_prices
  WHERE currency_code = 'USD'
)
  6. bill: Those warehouses' billed $ per hour at list price. A query's estimated $ is the hour's $ times its share of the hour's work.
    Its SQL (13 lines)
    -- Those warehouses' billed $ per hour at list price. A query's estimated $ is the hour's $ times its share of the hour's work.
bill AS (
  -- those warehouses' billed $ per hour, at list price
  SELECT CAST(u.usage_metadata.warehouse_id AS STRING) AS warehouse_id, date_trunc('HOUR', u.usage_start_time) AS hr,
         SUM(u.usage_quantity * p.list_rate) AS usd
  FROM system.billing.usage u
  JOIN price p
    ON p.sku_name = u.sku_name AND p.cloud = u.cloud AND p.usage_unit = u.usage_unit
   AND u.usage_end_time >= p.price_start_time AND (p.price_end_time IS NULL OR u.usage_end_time < p.price_end_time)
  WHERE u.usage_date >= CAST(CAST(:time_range.min AS DATE) AS DATE) AND u.usage_date < CAST(date_add(:time_range.max, 1) AS DATE)
    AND CAST(u.usage_metadata.warehouse_id AS STRING) IN (SELECT warehouse_id FROM q)
  GROUP BY 1, 2
)

One row per dashboard, tab, day, identity and warehouse; newest first.

-- Final SELECT: the rows the widgets read.
SELECT b.dashboard, q.tab, q.day, q.executed_by AS run_as,
       COALESCE(wh.warehouse_name, q.warehouse_id, 'No warehouse') AS warehouse,
       COUNT(*) AS queries,
       SUM(CASE WHEN q.execution_status = 'FAILED' THEN 1 ELSE 0 END) AS failed,
       SUM(CASE WHEN q.cached THEN 1 ELSE 0 END) AS cached,
       ROUND(SUM(q.duration_ms) / 3600000, 3) AS hours,
       ROUND(SUM(q.queued_ms) / 3600000, 3) AS queued_hours,
       ROUND(MAX(q.duration_ms) / 1000, 1) AS slowest_s,
       ROUND(SUM(q.read_bytes) / 1e9, 2) AS gb_read,
       ROUND(SUM(COALESCE(bl.usd * q.weight_ms / NULLIF(a.all_ms, 0), 0)), 2) AS est_usd
FROM q
JOIN boards b ON b.slug = q.slug
LEFT JOIN wh ON wh.warehouse_id = q.warehouse_id
LEFT JOIN all_work a ON a.warehouse_id = q.warehouse_id AND a.hr = q.hr
LEFT JOIN bill bl ON bl.warehouse_id = q.warehouse_id AND bl.hr = q.hr
GROUP BY ALL
ORDER BY q.day DESC, hours DESC
