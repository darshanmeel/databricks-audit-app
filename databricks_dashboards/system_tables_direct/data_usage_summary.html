Data usage, in brief

A two-minute read. Every query, step and column: the detailed guide.

What it is for

The app's Data usage section as a dashboard: an overview, workspaces, tables and volumes in one usage class each, people, and detail pages for one workspace, table or person. For every workspace.

How the tables join

Grey: system tables. Blue border: a shared check (its steps are listed under Steps). White: steps of the query. Green: the rows the dashboard shows. ◆ marks the columns the joins use.

  1. access.table_lineage → home: most reads and writes
  2. access.table_lineage → c: reads, writes, last use
  3. home → c: ON catalog
  4. information_schema → c: tables, tags
  5. table_sizes / volume_sizes (job) → c: bytes, files
  6. access.audit → people per workspace: events
  7. query.history → people per workspace: queries
  8. c → workspaces, tables, volumes, people, details: per workspace, per table
  9. people per workspace → workspaces, tables, volumes, people, details: LEFT JOIN ON workspace_id

                              How it works

                              • Lineage gives each catalog its home workspace, and each table its reads, writes and last use.
                              • The class rules put every table and volume in one class; information_schema adds columns, tags and grants.
                              • Audit and query history give the people; the sizes job adds bytes and files.

                              Example: one workspace, from lineage to the dashboard

                              The query, simplified

                              The core of it; runs as is in a SQL editor. The dashboard's full queries, step by step: the detailed guide.

                              -- Each table's usage class in the last 30 days, simplified.
WITH used AS (
  SELECT full_name, SUM(is_read) AS reads, SUM(is_write) AS writes FROM (
    SELECT source_table_full_name AS full_name, 1 AS is_read, 0 AS is_write FROM system.access.table_lineage
    WHERE event_date >= current_date() - 30
    UNION ALL
    SELECT target_table_full_name, 0, 1 FROM system.access.table_lineage WHERE event_date >= current_date() - 30
  ) GROUP BY 1
)
SELECT full_name,
       CASE WHEN writes > 0 AND reads = 0 THEN 'Written, never read'
            WHEN reads = 0 THEN 'Cooling or idle' ELSE 'Active' END AS usage_class
FROM used;

                              The pages

                              PageWhat it shows
                              OverviewWhere the data sits by how it is used, who reads and writes it, and what to clean up, for the workspaces and the window picked above. Every chart follows the filters.
                              WorkspacesEvery workspace: its tables by class, what it holds, how much work happens in it, and its signal. Open a workspace, or pick it on Workspace detail.
                              Workspace detailPick one workspace: its schemas, its tables by class, its reads and writes per day, and its people.
                              TablesEvery table and view in one usage class: what is read, what is written but never read, and what sits idle. Open one in Catalog Explorer, or pick it on Table detail.
                              Table detailPick one table: its reads and writes per day, who reads and writes it, who can read it but doesn't, its sensitive columns, where it comes from and goes, and its change history.
                              VolumesEvery volume in one usage class: files and size from the daily listing, file reads and writes from the audit log.
                              PeopleWho reads and writes, who writes what nobody reads, who touched sensitive data, and who stopped coming but can still read. Pick one person on Person detail.
                              Person detailPick one person or service principal: where they work, and every table they read or wrote.

                              The rules

                              TermMeans
                              Home workspaceThe workspace with the most lineage reads and writes of a catalog over 90 days.
                              Usage classWritten, never read: Something pays to write data nobody reads. Pause the writer.; Idle 90d+: No read and no write in 90 days. Archive or drop.; Cooling: Not read in the window, used within 90 days. Ask the owner.; Active: Read in the window. Check who reads and who writes it.
                              Complexity indexViews 20, view columns 15, tables 20, table columns 15, volume files 10, table size 20; each on a log scale against the largest workspace shown.
                              Usage indexPeople 35, service principals 15, queries 30 (log scale); active days / window days 20.
                              SignalUsage under 10: Retire candidate. Complexity 50+ and usage under 50: Review. Complexity under 50: Light. Else Healthy.
                              Sensitive columnA column tag starting pii, sensitive, gdpr or class., else a column name such as email, phone, iban, birth.
                              InactiveNot seen in the workspace for 90+ days within the last year.

                              Good to know

                              • Sizes and volume files come from the sizes job; tables it can't read show no size.
                              • A catalog with no lineage in 90 days has no home workspace: No home workspace.
                              • Direct table grants only; schema, catalog and group grants aren't expanded. A group's grant reads never used.
